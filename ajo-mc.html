O que é o Adobe Journey Optimizer?

O Adobe Journey Optimizer (AJO) é a plataforma de orquestração de jornadas de clientes da Adobe, construída nativamente sobre a Adobe Experience Platform (AEP). Diferente de ferramentas de e-mail marketing tradicionais, o AJO combina comunicações em batch (campanhas agendadas) com jornadas em tempo real disparadas por eventos — tudo a partir de um único canvas.

Lançado em 2021 como sucessor do Adobe Campaign Standard, o AJO herdou as capacidades de orquestração e as expandiu com perfil unificado em tempo real, suporte a múltiplos canais nativos, decisioning com IA e uma arquitetura API-first baseada em AEP.

📌 AJO vs Adobe Campaign vs SFMC

O AJO não é simplesmente um "Adobe Campaign moderno" — é uma plataforma diferente em arquitetura. Enquanto o Campaign Classic/Standard opera sobre bancos de dados proprietários, o AJO opera sobre o Real-Time Customer Profile da AEP, o que muda fundamentalmente como os dados fluem e como a personalização acontece.

Base: Adobe Experience Platform

O AJO não é uma ferramenta isolada — é uma das quatro aplicações nativas construídas sobre a AEP, junto com Real-Time CDP, Customer Journey Analytics e Adobe Mix Modeler.

Real-Time Customer Profile

O coração do AJO é o Real-Time Customer Profile da AEP. Ele agrega dados de múltiplas fontes em um único perfil unificado por contato, disponível em milissegundos para personalização e decisão em tempo real.

  • Identity Graph: une diferentes IDs do mesmo usuário (e-mail, ECID, CRM ID, ID mobile) em um único perfil
  • XDM Schemas: esquema padronizado (Experience Data Model) que garante que dados de fontes distintas sejam interpretados de forma consistente
  • Datasets: conjuntos de dados ingeridos na AEP — equivalente às Data Extensions do SFMC, mas com suporte nativo a streaming e batch
  • Computed Attributes: atributos calculados a partir de comportamentos históricos (ex: soma de compras nos últimos 90 dias) persistidos no perfil

Audiences e segmentos

Os Audiences no AJO são equivalentes às listas do HubSpot ou às Data Extensions filtradas do SFMC — mas construídos sobre o perfil unificado da AEP e com suporte a avaliação em tempo real.

TipoComo funcionaLatência
Batch SegmentationAvaliação agendada (diária) — ideal para campanhas de alto volumeHoras
Streaming SegmentationQualificação em tempo real conforme novos eventos chegamSegundos
Edge SegmentationAvaliação no dispositivo/edge para personalização imediataMilissegundos

✅ Channel Configuration

Cada canal precisa de uma Channel Configuration (superfície) configurada antes de ser usado em journeys ou campaigns — define remetente, subdomínio, provider de SMS, app mobile etc. Essa configuração é feita pela equipe de administração e é reutilizável entre campanhas.

Journeys — jornadas de clientes

As Journeys são o canvas visual do AJO onde você orquestra sequências de interações — desde jornadas simples de boas-vindas até fluxos complexos de ciclo de vida com múltiplos canais e decisões em tempo real.

Existem três tipos principais de Journey:

TipoGatilhoUso típico
Event-triggeredEvento de experiência em tempo real (compra, cadastro, clique)Triggered de abandono, boas-vindas, transacional
Audience-triggeredEntrada em um Audience (batch ou streaming)Campanhas de nutrição, reengajamento, lifecycle
Read AudienceLeitura de um Audience em horário agendadoNewsletter semanal, campanha recorrente

Eventos — triggers da jornada

Os Eventos são sinais externos que disparam ou influenciam jornadas. No AJO, dividem-se em:

  • Unitary events: relacionados a um perfil específico — ex: compra realizada, formulário submetido. Disparados via API (Streaming Ingestion) ou conectores.
  • Business events: não estão relacionados a um perfil individual — ex: mudança de estoque, resultado de uma partida esportiva. Podem reentrar contatos em jornadas.
  • Audience Qualification: um perfil entra ou sai de um Audience — funciona como gatilho de evento para a jornada.

Condições e branches

As Condition activities dividem o fluxo com base em atributos de perfil, eventos ou dados contextuais. Funcionam como o Decision Split do SFMC Journey Builder.

  • Profile condition: baseada em atributos do perfil unificado ou de audiences
  • Event condition: baseada em dados do evento que disparou a jornada
  • Time condition: baseada em horário ou dia da semana
  • Data source condition: consulta dados de uma fonte externa via custom action

Ações e esperas

Ações executam a entrega de mensagens ou chamadas externas. Wait activities pausam o fluxo por um tempo definido ou até uma data específica.

AtividadeO que faz
Message (canal)Envia e-mail, push, SMS, in-app etc. com personalização
WaitAguarda X horas/dias ou até data/horário específico
Custom ActionChama uma API externa (CRM, DMP, sistema de pontos)
Update ProfileAtualiza um atributo no Real-Time Customer Profile
Audience (Add/Remove)Adiciona ou remove o perfil de um Audience
JumpEncaminha para outro Journey
EndFinaliza a jornada para o perfil
⚠ Timeout global de Journey

Cada Journey tem um timeout global (padrão: 30 dias, máximo: 91 dias). Perfis que ainda estão na jornada após esse prazo são automaticamente saídos. Configure esse valor de acordo com o ciclo esperado da jornada.

Campaigns — envios em batch e agendados

As Campaigns são a modalidade para comunicações de marketing em massa — equivalente a um envio de e-mail para uma lista no SFMC ou HubSpot. A diferença é que mesmo em campaigns, o AJO usa o perfil unificado da AEP para personalização.

TipoQuando usar
Scheduled CampaignEnvio único ou recorrente em data/hora definida para um Audience
API-triggered CampaignDisparada via API — útil para mensagens transacionais ou com dados contextuais externos

A partir de 2025, o AJO também introduziu Campaign Orchestration (Orchestrated Campaigns) — campanhas multietapas com lógica de targeting mais avançada para operações de marketing em batch de alto volume.

Personalização

Expression Editor — personalização com Handlebars

O AJO usa uma sintaxe baseada em Handlebars (e Helper Functions proprietárias da Adobe) para personalização — bem diferente do AMPscript do SFMC. As expressões acessam o perfil unificado, dados de evento e contexto em tempo real.

Tipo de expressãoSintaxeO que acessa
Atributo de perfil{{profile.person.name.firstName}}Dados do Real-Time Profile (XDM)
Evento contextual{{context.journey.events.purchase.amount}}Dados do evento que disparou a jornada
Condicional inline{{#if profile.segmentMembership...}}Lógica if/else no conteúdo
Helper function{{dateFormat now "dd/MM/yyyy"}}Funções nativas: datas, strings, math
Fallback / default{{profile.person.name.firstName default="cliente"}}Valor quando campo está vazio
✅ Personalization Playground

O AJO oferece um Personalization Playground onde você pode testar expressões com payloads de exemplo antes de usar em produção — equivalente ao Preview do SFMC, mas focado nas expressões de personalização.

Offer Decisioning — a melhor oferta no momento certo

O Decisioning (anteriormente Offer Decisioning) é o módulo de IA do AJO para selecionar automaticamente a melhor oferta para cada perfil em cada momento, com base em regras de elegibilidade, prioridades, capping e modelos de IA de ranking.

  • Offer Library: catálogo centralizado de ofertas com atributos, imagens e elegibilidade
  • Decision Rules: filtros que determinam quem é elegível para cada oferta
  • Ranking: prioridade manual ou modelo de IA (Auto-Optimization, Personalized Optimization)
  • Capping: limite de quantas vezes uma oferta pode ser mostrada por perfil ou no total
  • Placements: onde a oferta aparece (e-mail, web, in-app, push)

Integração com Salesforce Marketing Cloud

Uma das necessidades mais comuns em projetos de migração ou coexistência é trazer dados do SFMC para o AJO/AEP — ou usar audiências criadas na AEP para executar envios no SFMC. A AEP oferece dois mecanismos nativos para isso.

Source Connector — SFMC → AEP

O Salesforce Marketing Cloud Source Connector permite ingerir dados do SFMC na AEP, tornando-os disponíveis para o perfil unificado e para journeys no AJO.

1
Pré-requisitos no SFMC

Criar um Installed Package no SFMC com permissões: Automation Studio, Data Extensions, Email, List and Subscribers. Obter Client ID, Client Secret e o Subdomain (MID) da BU.

2
Configurar Source na AEP

Em Sources → Marketing Automation → Salesforce Marketing Cloud, criar uma base connection com as credenciais do SFMC (V2 connector recomendado). Selecionar qual Data Extension ou objeto (Contacts, Events, Emails Sent etc.) será ingerido.

3
Mapear para XDM Schema

No mapper da AEP, relacionar os campos da DE do SFMC (ex: SubscriberKey, EmailAddress) com os campos XDM correspondentes (ex: identityMap, personalEmail.address). Esse mapeamento define como os dados entrarão no perfil unificado.

4
Definir schedule de ingestão

Configurar ingestão incremental (delta) ou full refresh. Para dados transacionais de engajamento (opens, clicks), a ingestão incremental diária é o padrão mais comum. Dados de perfil de contato podem ter frequência menor.

5
Validar no Profile Viewer

Após a ingestão, validar no Profile Viewer da AEP se os registros do SFMC estão sendo corretamente unificados com perfis existentes via Identity Graph. Verificar se o SubscriberKey foi configurado como namespace de identidade.

⚠ Limite de Sources concorrentes

O AJO/AEP permite até 5 Sources não-Adobe concorrentes por padrão. Se você já tem outros conectores ativos (Salesforce CRM, Google Ads etc.), planeje o slot antes de adicionar o SFMC.

Destination — AEP → SFMC

O fluxo inverso — exportar Audiences criados na AEP para execução no SFMC — é feito via Destination. A AEP gera arquivos CSV em uma localização SFTP, que o SFMC importa via Automation Studio para uma Data Extension.

1
Configurar SFTP no SFMC

No SFMC, criar ou identificar um local de Enhanced FTP onde a AEP depositará os arquivos de exportação de audiências.

2
Criar Destination na AEP

Em Destinations → Marketing → Salesforce Marketing Cloud, conectar o SFTP e mapear os campos do perfil XDM para as colunas do CSV exportado.

3
Ativar o Audience para o Destination

Selecionar o Audience desejado na AEP e ativá-lo para o Destination do SFMC. Definir frequência de exportação e atributos incluídos no arquivo.

4
Automation no SFMC para importar

Criar uma Automation no SFMC que monitora o SFTP, importa o arquivo CSV para uma Data Extension e, opcionalmente, inicia um journey ou envio de e-mail com a audiência atualizada.

Boas práticas

✅ Projete os XDM Schemas antes de tudo

A arquitetura de dados na AEP define tudo que o AJO pode fazer. Schemas mal projetados são difíceis de corrigir depois que dados já foram ingeridos. Antes de conectar qualquer fonte, documente quais atributos são necessários para personalização e segmentação e mapeie para XDM com cuidado.

✅ Use Sandboxes para desenvolvimento

O AJO inclui até 5 Sandboxes. Sempre desenvolva e teste jornadas em uma sandbox de dev/QA antes de publicar na produção. A partir de 2025, é possível copiar objetos de Decisioning entre sandboxes, o que acelera o processo de promoção.

✅ Configure Frequency Capping e Quiet Hours

O AJO tem rule sets nativos para Frequency Capping (limitar quantas mensagens um perfil recebe por período) e Quiet Hours (não enviar em horários indevidos). Configure esses limites globalmente antes de ativar qualquer jornada para evitar sobrecomunicação.

⚠ Monitore Profile Discard Rate

Uma das métricas mais importantes no AJO é a Profile Discard Rate — percentual de perfis que entram na jornada mas são descartados por erro (dados inválidos, timeout, política de capping). O AJO 2026 introduziu alertas automáticos quando essa taxa excede o threshold configurado.

⚠ Não confunda Journey com Campaign

Use Journeys para orquestrações baseadas em comportamento e tempo (event-triggered, multi-step com waits). Use Campaigns para envios únicos ou agendados para um Audience estático. Usar Journey onde deveria ser Campaign gera overhead desnecessário na plataforma.
